# 页栖界面升级设计

## 1. 背景与目标

PageNest 当前以 HandyReader 为功能基线，已经具备本地书籍导入、EPUB/TXT/PDF/MOBI/AZW3 阅读、阅读进度、图片换肤和在线/离线语音阅读能力，但品牌、首次启动流程和核心页面仍保留上游产品痕迹，界面层级也没有围绕页栖的产品定位统一。

本轮升级建立页栖自己的视觉系统，参考微信读书在信息层级、留白、阅读沉浸和操作收纳上的成熟做法，但不复制其商标、插画、图标或专属素材。核心目标如下：

- 全面使用“页栖 / PageNest”品牌，移除用户可见的 HandyReader 文案。
- 以蓝绿渐变建立清爽、科技感明确且适合 HyperOS 3 的品牌视觉。
- 重做书架首页、阅读器和“我的”三个核心页面。
- 保留现有阅读、导入、设置、换肤、语音与数据持久化行为。
- 任何解析、换肤或语音失败均通过可恢复状态呈现，不允许拖垮主页面。
- 每阶段采用 TDD，完成测试、Lint、APK 构建、提交和远端推送。

## 2. 已确认的视觉方向

### 2.1 品牌配色

- 主渐变：青绿 `#18A69D` 到科技蓝 `#397DE4`。
- 强调青绿：`#18A69D`，用于选中态、阅读进度和轻量反馈。
- 科技蓝：`#397DE4`，用于渐变末端和重点数据。
- 应用背景：低饱和冷白或浅灰蓝，不大面积使用高饱和渐变。
- 阅读背景：暖米白，避免长时间阅读刺眼。
- 深色阅读背景：柔和墨黑，正文保持足够对比度但避免纯白强光。

所有颜色通过 Compose 主题令牌提供。页面不得散落硬编码品牌色；图片换肤产生的动态颜色除外。

### 2.2 应用图标

采用“阅读窗口”方向：

- 蓝绿渐变圆角方形底色。
- 中央为白色书页/阅读窗口。
- 配合青绿书签与蓝色完成标记。
- 在 HyperOS 桌面小尺寸下仍能识别，不使用细小文字。
- 生成 Android adaptive icon 的前景、背景及兼容位图资源。

### 2.3 页面方向

- 首页：B“阅读仪表盘”。
- 阅读器：A“沉浸留白”。
- “我的”：B“功能中心”。

## 3. 设计系统

新增 `PageNestDesignSystem`，由主题令牌和可复用组件组成，不改写现有业务层接口。

### 3.1 主题令牌

- `PageNestColors`：浅色、深色、阅读浅色、阅读深色和动态图片背景的语义颜色。
- `PageNestTypography`：大标题、页面标题、卡片标题、正文、辅助信息和阅读正文层级。
- `PageNestShapes`：大卡片、中卡片、按钮、弹层、书封和标签圆角。
- `PageNestSpacing`：页面边距、卡片间距、列表间距和最小触控区域。
- `PageNestGradients`：品牌主渐变和低对比背景渐变。

### 3.2 通用组件

- 品牌渐变卡片。
- 阅读数据卡片。
- 统一空状态、加载状态、导入进度和错误提示。
- 统一顶部栏、底部导航、功能入口卡片和设置行。
- 统一阅读器浮动工具栏和语音迷你播放器。

组件只接收展示模型和事件回调，不直接读取数据库、文件或语音服务。

## 4. 信息架构与导航

主导航固定为：

1. 书架：首页与书籍管理。
2. 阅读：最近阅读、当前阅读或阅读历史入口。
3. 我的：功能中心与设置入口。

保留现有详情、目录、笔记、统计、设置、PDF 阅读器和音频阅读器路由。第一阶段不迁移路由框架，只统一目的地名称、图标、转场和选中态。

## 5. 核心页面

### 5.1 首次启动

- 使用“页栖”名称和新图标。
- 默认文案为中文，并保留可本地化资源结构。
- 用户可选择书籍目录，也可跳过进入空书架。
- 跳过不自动依赖示例 EPUB/MOBI 成功解析。
- 示例书导入或解析失败时记录失败并提示，不终止应用。

### 5.2 阅读仪表盘首页

首页顶部显示“今天读书了吗”和页栖入口。首屏展示：

- 今日阅读分钟。
- 连续阅读天数。
- 本周阅读目标完成度。
- 最近阅读列表：封面、书名、章节/位置、最后阅读时间和进度。

页面同时提供搜索、排序、书架切换和一键导入。空书架显示导入引导；加载、导入和错误状态使用统一组件。现有网格/列表能力可保留为“全部书籍”视图，不与仪表盘首屏争夺层级。

### 5.3 沉浸式阅读器

默认只展示正文、章节和页码。轻触正文后显示：

- 目录。
- 阅读进度。
- 听书。
- 显示设置。

工具栏在超时或再次轻触后隐藏。语音播放启动后显示精简播放器，包含暂停/继续、倍速、定时关闭和当前引擎；后台播放状态继续由现有媒体服务持有。

字号、行距、字体、翻页方式、阅读背景和图片换肤跟随现有持久化规则。EPUB、TXT、MOBI/AZW3 与可提取文字 PDF 使用一致的视觉控件，但不强行合并格式特有的渲染逻辑。

### 5.4 “我的”功能中心

第一层功能入口：

- 语音阅读。
- 一键图片换肤。
- 笔记与书签。
- 阅读统计。

第二层管理入口：

- 书籍与存储。
- 在线语音 API。
- 外观与字体。
- 关于页栖。

API Key 页面只展示是否已配置，不回显完整密钥。页面不引入账号、会员或社交入口；首版继续保持本地优先定位。

## 6. 图片换肤与可读性

自定义图片只影响允许换肤的首页和阅读背景区域。应用必须：

- 根据背景亮度选择前景色或使用稳定遮罩。
- 保证正文、按钮和状态文字满足可读性要求。
- 图片处理失败时原子回退到之前的主题。
- 深色模式、系统模式和自定义图片的优先级保持明确并保存。
- 不让自定义图片覆盖关键操作控件。

## 7. 状态与异常处理

- 加载、空数据、导入中、导入成功、重复书籍和导入失败使用稳定 UI 状态。
- EPUB/MOBI 原生库缺失或格式不支持时，将书籍标记为解析失败并提供重试或移除，主页面继续可用。
- 图片换肤失败时保留原主题并清理未发布文件。
- 在线语音不可用时按现有路由策略回退离线语音，并显示当前引擎。
- PDF 没有可提取文字时仍允许视觉阅读，语音入口解释不可用原因。
- API Key、文件路径和语音错误不得泄露到面向用户的调试文案中。

当前 x86_64 模拟器可启动首次引导，但进入首页时会因 APK 不含 x86_64 `libappmobi.so` 而崩溃。UI 改造必须先隔离示例书解析失败，使首页不因单本示例书或单个解析器失败而退出。ARM64 真机仍是 EPUB/MOBI 最终验收环境。

## 8. 测试策略

严格执行红、绿、重构：

- JVM 单元测试：主题令牌、品牌文案、导航策略、首页展示模型、工具栏可见性、语音控件状态和解析失败降级。
- Compose UI 测试：首页仪表盘、阅读器工具栏、“我的”功能中心、首次启动、空状态和深色模式。
- 构建验证：单元测试、Android 测试 APK、Lint 和 Debug APK。
- 模拟器验证：首次启动、跳过、空书架、导航和普通 UI 流程。
- HyperOS 3 ARM64 真机验证：安装、EPUB/TXT/PDF/MOBI/AZW3 导入与打开、阅读进度、图片换肤、在线/离线语音及后台播放。

## 9. 分阶段交付

### 阶段 1：品牌与视觉基础

- 设计系统令牌和基础组件。
- 中文品牌与首次启动页。
- “阅读窗口”应用图标。
- 隔离示例书解析失败，保证可进入首页。

### 阶段 2：首页

- 阅读仪表盘。
- 最近阅读、阅读数据和空状态。
- 搜索、排序、导入和全部书籍入口。

### 阶段 3：阅读器

- 沉浸正文。
- 显隐工具栏。
- 目录、进度、听书和显示入口。
- 语音迷你播放器。

### 阶段 4：“我的”与设置

- 功能中心。
- 语音、换肤、笔记、统计和设置入口统一。
- 次级设置页面视觉统一。

### 阶段 5：收口与发布

- 导入、详情、统计、弹窗等次级页面统一。
- 模拟器回归和 HyperOS 3 ARM64 真机验收。
- 版本号更新、APK 构建、GitHub Release 和 SHA-256 归档。

每个阶段完成后执行完整的相关测试和构建，提交并推送 `master`。只有达到可安装和可回归的发布检查点才创建新的 GitHub Release。

## 10. 非目标

- 不复制微信读书的专属素材、图标、商标或逐像素布局。
- 不在本轮引入账号、社区、会员、在线书城或后端服务。
- 不重写解析器、数据库或媒体服务架构。
- 不以主题替换为由删除现有阅读、换肤或语音能力。
