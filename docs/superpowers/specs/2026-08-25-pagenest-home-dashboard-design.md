# 页栖第 2 阶段：首页阅读仪表盘设计

## 1. 阶段目标

本阶段把现有以书籍网格/列表为主体的首页升级为“阅读仪表盘”，让用户打开页栖后首先看到阅读状态、最近阅读和继续阅读入口，同时保留搜索、排序、书架切换、导入及全部书籍管理能力。

本阶段只调整首页展示与数据编排，不重写数据库、解析器、阅读器或导航框架，不引入账号和网络服务。

## 2. 已确认方案

采用“独立展示模型 + 纯数据计算器 + 无状态 Compose 界面”的方案：

- `HomeDashboardModel` 描述首页所需的稳定展示数据。
- `HomeDashboardCalculator` 根据本地书籍、阅读活动、当前日期和周目标生成展示模型。
- `HomeDashboardContent` 只接收展示模型与事件回调，不直接访问数据库、文件或 ViewModel。
- `HomeViewModel` 复用现有书籍仓库，并接入现有阅读活动用例，向界面暴露仪表盘状态。
- 现有网格/列表能力作为“全部书籍”区继续使用，不删除原有书架管理能力。

不采用把统计逻辑直接写进旧书架 Composable 的方案，以避免界面和业务状态继续耦合；也不新建独立导航目的地，以控制本阶段的回归范围。

## 3. 页面结构

首页从上到下分为以下层级：

1. 品牌问候区：显示“今天读书了吗”和轻量日期提示。
2. 蓝绿渐变阅读概览卡：显示今日阅读分钟、连续阅读天数和本周目标完成度。
3. 最近阅读区：最多展示 3 本最近打开的非音频书籍，包含封面、书名、作者或阅读位置、最后阅读时间、进度与继续阅读操作。
4. 快捷操作区：提供一键导入与进入全部书籍的明显入口。
5. 全部书籍区：保留现有书架标签、搜索、排序、网格/列表切换和选择管理能力。

首页使用阶段 1 已建立的 `PageNestTheme`、品牌渐变、圆角和间距令牌。自定义背景图片仍由现有换肤机制提供，并通过遮罩保证卡片与文字可读。

## 4. 数据定义与计算规则

### 4.1 今日阅读

- 读取 `ReadingActive` 中系统时区下属于今天的记录。
- 合计毫秒数并向下取整为分钟；不足 1 分钟显示 0 分钟。
- 同一天存在多条记录时合计，避免依赖数据库是否已经聚合。

### 4.2 连续阅读

- 只把单日累计达到 1 分钟视为有效阅读日。
- 从今天开始向前计算；今天尚未阅读时，允许从昨天开始延续连续天数。
- 如果最近有效阅读日早于昨天，连续天数为 0。
- 同一天重复记录只计作一天。

### 4.3 本周目标

- 首版本周目标固定为 150 分钟，后续阶段可迁移为用户设置。
- 周一为一周开始，合计本周有效阅读时长。
- 进度限制在 0% 到 100%；超过目标时仍显示实际分钟数，但进度条满格。

### 4.4 最近阅读

- 排除音频书籍；音频书继续由现有有声书入口管理。
- 按 `lastOpened` 降序排列，未打开过的书不进入最近阅读。
- 最多显示 3 本。
- 阅读进度限制在 0 到 100；位置优先显示可用的 `locator`，否则显示百分比。

## 5. 状态与交互

- 有最近阅读：点击书卡或“继续阅读”沿用现有按文件类型打开逻辑。
- 无最近阅读但有书：显示“选择一本书开始阅读”，并可进入全部书籍。
- 空书架：显示清晰的导入引导和“一键导入”按钮，不展示伪造统计或示例数据。
- 数据加载中：使用稳定占位状态，避免页面闪烁或错误显示空书架。
- 阅读统计读取失败：概览降级为 0，不阻断书架、搜索或导入。
- 导入进度、重复书籍、失败提示继续使用现有 Snackbar 与导入状态。
- 搜索、排序、布局和书架切换继续复用现有操作，不改变持久化规则。

## 6. 数据流

1. `HomeViewModel` 订阅全部书籍和全部阅读活动。
2. ViewModel 将原始数据与当前时间传给纯计算器。
3. 计算器生成不可变 `HomeDashboardModel`。
4. `HomeScreen` 收集状态并传给无状态 `HomeDashboardContent`。
5. 用户事件通过回调返回 `HomeScreen`/`HomeViewModel`，复用现有打开书籍、导入、搜索和排序逻辑。

计算器不读取 Android Context，日期通过参数注入，使跨天、跨周与时区边界可在 JVM 测试中稳定复现。

## 7. 错误边界与兼容性

- 阅读活动 Flow 发生异常时捕获普通异常并输出空活动列表；协程取消继续向上传播。
- 单本书封面加载失败时显示统一占位封面，不影响其他书籍。
- 最近阅读打开仍沿用 EPUB/TXT/MOBI/AZW3、PDF 和音频的现有路由分支。
- 最低 Android 版本、HyperOS 3 适配、图片换肤、语音能力和存储权限行为不在本阶段改变。
- x86_64 模拟器继续依赖阶段 1 的可选示例书解析隔离；ARM64 真机仍是格式解析最终验收环境。

## 8. TDD 与验收

严格按红、绿、重构执行：

1. JVM 单元测试先覆盖今日分钟、跨日连续阅读、昨天延续、断档归零、周一起点、目标封顶、重复日期和最近阅读排序。
2. Compose UI 测试先覆盖概览文案、最近阅读、空书架导入按钮、全部书籍入口和回调。
3. 接线测试验证 ViewModel 正确组合书籍和阅读活动，失败时可降级。
4. 完成后运行相关单元测试、全部单元测试、Android 测试 APK、Debug APK 与 Lint。
5. 在 API 36 模拟器验证浅色/深色、空书架、最近阅读、继续阅读、导入入口和返回路径；在可用时补充 HyperOS 3 ARM64 真机验证。

## 9. 完成标准

- 首页默认呈现阅读仪表盘，不再由大片空白书架占据首屏。
- 今日阅读、连续天数和本周目标来自真实本地数据。
- 最近阅读可直接恢复阅读，空状态可一键进入导入流程。
- 旧书架的搜索、排序、布局、选择和书架管理功能仍可使用。
- 浅色、深色和图片换肤背景下内容可读。
- 相关测试、构建和 Lint 通过，阶段记录已归档。
- 每个任务提交并推送 `master`；达到可安装检查点后更新版本并把 APK、SHA-256 发布到 GitHub Releases。
