# PageNest 语音阅读设计

## 1. 目标

为 PageNest 增加可长期使用的小说语音阅读能力，并在目标设备 HyperOS 3 / Android 16 上完成真实验收。

首版必须满足：

- 支持 EPUB、TXT、MOBI、AZW3，以及能够提取正文文本的 PDF。
- 同时支持离线系统 TTS 与在线高质量 TTS。
- 支持后台、锁屏和通知栏控制。
- 朗读位置与阅读页高亮同步，并保存最后完成朗读的进度。
- 在线失败时可靠回退到离线，不中断用户的阅读会话。
- 用户可配置在线服务 API Key，密钥和正文不得出现在日志、备份或仓库中。

纯图片扫描 PDF 不做 OCR。若整本 PDF 均无可提取文本，应用明确提示“此 PDF 为扫描版，暂不支持语音朗读”。

## 2. 已确认的产品决策

- 引擎模式：在线 + 离线。
- 后台能力：支持前台媒体服务、通知栏和锁屏控制。
- 格式范围：五种导入格式全部纳入；PDF 仅朗读可提取文本。
- 阅读联动：当前段落高亮并自动跟随；仅在一段朗读完成后保存该段末尾进度。
- 在线认证：允许用户配置 API Key。
- 首个正式云供应商：Azure AI Speech，使用用户提供的 Speech Key 与 Region。
- 在线合成模式：实时、按段落流式合成；不使用批量长音频接口，也不预生成整本书。
- 默认模式：自动。优先使用用户选定且已正确配置的在线音色；不可用时回退系统 TTS。

现有非正式 Edge TTS 连接不得作为发布能力依赖。首版在线实现只使用 Azure 官方接口；云供应商必须位于适配器之后，便于未来增加其他正式供应商。

## 3. 架构

### 3.1 统一朗读内容

阅读器把各格式内容转换为 `SpeechSegment` 流。每个段落至少包含：

- `bookId`
- `chapterId` 或 PDF 页码
- 稳定的段落序号
- 规范化正文文本
- 阅读器可恢复定位信息
- 原始文本范围，用于当前段落高亮

EPUB、TXT、MOBI、AZW3 以章节正文为边界。PDF 逐页提取文本，移除空白页；有文本的页面继续按段落切分。任一云请求最多包含 500 个 Unicode 码点，超长段落在自然标点处切分，但所有子段共享同一阅读定位。

`SpeechContentSource` 只负责产出段落，不负责播放、网络或进度写入。这样解析器、队列和音频引擎可以分别测试。

### 3.2 会话控制

`SpeechSession` 是唯一的播放状态机，状态包括 `Idle`、`Preparing`、`Playing`、`Paused`、`Completed` 和 `Error`。它负责：

- 从当前可见段落开始建立队列。
- 跨页、跨章连续获取后续段落。
- 播放、暂停、继续、停止、上一段和下一段。
- 语速、音调、语言和音色配置。
- 在线失败重试、离线回退和用户提示。
- 当前段落高亮、页面跟随和进度提交。
- 定时关闭。

同一时间只允许一个活动会话。用户翻页、跳章、切书或改变引擎时，先取消旧队列及其合成请求，再从新定位创建会话，不能出现两路语音重叠。

### 3.3 引擎边界

统一 `SpeechEngine` 契约提供初始化、音色查询、合成/播放、暂停、停止和释放能力，并返回可分类错误。

- `SystemTtsEngine` 使用 Android `TextToSpeech`，是离线模式和最终回退引擎。
- `AzureSpeechEngine` 使用 Azure AI Speech 官方实时 TTS 接口、用户的 Speech Key 与 Region，并支持官方音色列表。
- `FallbackSpeechEngine` 实施自动模式策略，不包含 UI 逻辑。

Azure 请求使用与 Region 匹配的官方区域端点。Key/Region 错配、401/403、余额/限流、网络超时和服务端错误必须分类，不能统一吞成“播放失败”。Azure 官方 REST API要求请求携带区域匹配的密钥或 Bearer token，并支持 SSML 实时合成：[Azure Text to Speech REST API](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)。

### 3.4 后台播放

`SpeechPlaybackService` 是 Android 前台媒体播放服务并持有 `SpeechSession`。它通过 MediaSession 暴露：

- 播放/暂停
- 上一段/下一段
- 停止
- 当前书名、章节与播放状态

服务声明 Android 14+ 媒体播放前台服务类型和最小必要权限，不请求广泛存储权限。阅读页只观察会话状态，不直接持有 TTS 生命周期。

服务正确处理音频焦点：来电、导航等长期或短期抢占时暂停；焦点恢复后保持暂停，由用户主动继续。耳机或蓝牙音频路由断开时立即暂停。应用进程重建后恢复最后已提交位置，但不得自动发声。

## 4. 用户体验

阅读页工具栏增加“朗读”入口。底部控制面板包含：

- 播放/暂停
- 上一段/下一段
- 语速和音调
- 语言和音色
- 离线、在线、自动三种模式
- 定时关闭
- 当前使用的引擎及回退提示

朗读开始时滚动并高亮当前段落。段落真正完成后才保存其末尾定位；暂停、取消、异常或进程死亡不能把未完成段落记为已读。

在线模式配置页包含 Azure Speech Key、Region 和“测试连接”。Key 输入后只能覆盖或删除，不能重新显示完整明文。自动模式在线失败时显示一次非阻塞中文提示，并从同一未完成段落切换到离线引擎。用户明确选择“仅在线”时不自动回退，而是暂停并显示具体错误。

## 5. 错误处理与回退

错误至少分为：

- 系统 TTS 未安装或语言数据缺失
- 在线 Key 未配置或无效
- Azure Region 不匹配
- 余额不足或请求限流
- 网络不可用或超时
- 云服务暂时不可用
- 格式无可朗读文本
- 音频解码或播放失败

自动模式的网络超时、限流和 5xx 错误最多重试 2 次，退避间隔为 500 ms 和 1500 ms；单次连接超时 10 秒，完整响应超时 30 秒。仍失败则取消该在线请求，从同一段落切换离线。认证、Region 或余额错误不重试，直接回退并提示用户修正配置。

取消必须优先传播，不得被包装成普通失败，也不得在用户停止或跳转后启动回退播放。

## 6. 隐私与安全

- Android Keystore 只保存不可导出的 AES 密钥；Azure Key 使用该密钥加密后存入应用私有存储。
- 密钥存储排除 Android 自动备份。删除在线配置时同时删除密文和相关缓存。
- 日志不得包含 API Key、认证头、书名、正文、完整文件路径或云端响应体。
- 在线请求只发送当前待朗读的小段文本，不上传整本书。
- 设置页首次启用在线朗读时明确告知用户：当前段落文本会发送给 Azure 生成语音。
- Azure 官方说明实时预置语音合成处理输入文本并返回音频，实时合成的输入文本与输出音频不保存在 Microsoft 日志中：[Azure TTS 数据、隐私与安全](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/speech-service/text-to-speech/data-privacy-security?tabs=custom-neural-voice&view=foundry-classic)。应用仍需把是否启用在线发送的决定交给用户。

在线音频缓存位于应用私有目录，只缓存当前书籍的当前章节，最大 128 MiB，按 LRU 淘汰。缓存项超过 24 小时自动删除；用户可在设置中立即清空。缓存键使用内容摘要和非敏感引擎参数，不包含正文或 Key。

## 7. 进度一致性

语音进度与视觉阅读共享现有阅读定位模型，但通过独立的 `SpeechProgressCommitter` 提交。规则如下：

- 段落开始：只更新临时高亮，不写持久进度。
- 段落完成：原子写入该段末尾定位。
- 用户跳转：取消当前段，保存最近一个已完成段落，再从目标位置重建队列。
- 播放错误：保留最近一个已完成段落，不跳过失败段。
- 跨章：上一章最后一段完成后才进入下一章并更新章节信息。

## 8. TDD 与验证

### 8.1 单元测试

- 五种格式的段落抽取和稳定定位。
- PDF 有文本、部分扫描页和整本扫描版边界。
- 长段落按自然标点切分且不丢字、不重复。
- 会话状态机、跨章队列、手动跳转和单会话约束。
- 自动/离线/仅在线策略和精确错误分类。
- 两次重试、超时、回退与取消优先传播。
- 仅完成段落提交持久进度。
- API Key 加密、覆盖、删除、备份排除和日志脱敏。
- 当前章缓存、128 MiB 上限、24 小时过期和清除。

### 8.2 契约与 Android 测试

- 使用假服务验证 Azure 请求认证、Region 端点、SSML 转义、长度限制和响应解码，不在普通测试中访问真实云服务。
- 验证系统 TTS 初始化、缺失语言数据、暂停、停止和资源释放。
- 验证前台服务、MediaSession、通知动作、音频焦点和耳机拔出。
- 验证进程重建只恢复位置、不自动播放。
- 用可控假时钟验证定时关闭、重试与缓存过期，不使用真实 sleep。

### 8.3 HyperOS 3 / Android 16 真机

目标手机必须完成并记录：

- 五种格式的开始、暂停、继续、上一段、下一段和跨章朗读。
- 可提取文字 PDF 正常朗读；扫描版 PDF 显示正确提示。
- 系统中文离线音色；断网后自动回退。
- 有效和无效 Azure Key/Region；在线中文音色；网络切换与限流模拟。
- 锁屏、切后台、熄屏、通知栏控制、来电/其他音频焦点和耳机拔出。
- 高亮跟随、手动翻页、进度保存、杀进程后恢复。
- 连续朗读至少 60 分钟，检查崩溃、内存、耗电和设备温度。

真机未连接时必须记录 `NOT RUN (no connected device)`，不得宣称发布门禁通过。

## 9. 实施切片

1. 建立段落模型、内容源和格式特征测试。
2. 重构现有 TTS 代码到 `SpeechEngine` 契约，先完成稳定离线引擎。
3. 实现会话状态机、高亮和进度提交。
4. 实现前台媒体服务、MediaSession、音频焦点和通知控制。
5. 实现 Keystore 密钥仓库、Azure 官方适配器和在线设置页。
6. 实现自动回退、缓存、超时和错误提示。
7. 完成 Android 仪器测试和 HyperOS 3 真机验收。

每个切片严格执行 RED → GREEN → 重构、独立复审、本机完整复验、Conventional Commit，并推送 GitHub `master`。

## 10. 完成标准

- 五种格式中的可提取正文可以从当前段落连续朗读并跨章。
- 在线、离线和自动模式行为明确；自动模式能从同一段可靠回退。
- 后台、锁屏、通知、音频焦点和耳机事件行为正确。
- 当前段落高亮和已完成段落进度保持一致。
- API Key、正文、文件路径和云响应不泄露到日志或备份。
- 自动化测试、Debug/AndroidTest 构建、lint 和 HyperOS 3 真机门禁全部有可审计证据。
- 所有阶段提交均已推送到远端 `master`。
